# Chrome Web Store submission — VANI 0.1.0

The extension is implemented and can be installed unpacked now. A store submission still requires the owner's Chrome Web Store publisher account and its dashboard declarations. No store item has been created or published by this build.

## Upload files

- Extension ZIP: repository root `dist/vani-chrome-extension-0.1.0.zip`, generated by `npm run extension:package`. Upload this ZIP, not the source tree or a ZIP containing a parent folder.
- Icon: `apps/extension/icons/128.png`.
- Small promotional image: `apps/extension/store/promo-440x280.png`.
- Screenshots: `apps/extension/store/capture-1280x800.png` and `apps/extension/store/settings-1280x800.png`. These demonstrate the running extension with sample research/test data.
- Privacy policy: [privacy.md](privacy.md). Use a publicly accessible version in the dashboard, for example the repository page after verifying that it is publicly readable: `https://github.com/dkkarthik/vani/blob/main/apps/extension/store/privacy.md`.

## Listing copy

**Name:** VANI — Save academic papers

**Summary:** Save academic papers, metadata, source links, and available PDFs into your local VANI research collections.

**Suggested category:** Productivity; use an academic/research subcategory if offered by the dashboard.

**Description:**

Save the paper you are reading into your local VANI research workspace.

- Capture scholarly metadata from publisher, arXiv, and OpenReview article pages.
- Look up a DOI through Crossref and review the retrieved details.
- Choose an existing research collection or create one from the popup.
- Include an available PDF with permission for its download site.
- Keep source links and clear save status. Retry a PDF failure without losing the saved paper.
- Reuse papers and PDF attachments on repeat capture.
- Open the saved paper directly in VANI.

Requires a running local VANI installation. Connect using the capture key in VANI Settings. This version supports HTTP localhost/127.0.0.1 service addresses, selected HTTPS PDF downloads up to 50 MB, and one most recent capture for retry. Publisher access restrictions still apply. It does not bypass paywalls or guarantee metadata/PDF support on every website.

The extension has no analytics or advertising. See the privacy policy for local storage, DOI lookup, publisher download requests, and the separate VANI application's processing.

Setup and support: `https://github.com/dkkarthik/vani/blob/main/docs/15-browser-capture.md`

## Single purpose and permission explanations

**Single purpose:** Save user-selected academic papers, their bibliographic metadata, source links, and optional PDFs into the user's local VANI research collections.

| Permission                                 | Dashboard explanation                                                                                                                                                                                      |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `activeTab`                                | Read the article tab the user explicitly invokes, without ongoing access to all browsing.                                                                                                                  |
| `scripting`                                | Extract scholarly metadata and PDF links from that selected page, in an isolated script context.                                                                                                           |
| `storage`                                  | Persist the local connection key/settings, last collection, and one latest capture so status and retry survive popup closure.                                                                              |
| `http://127.0.0.1/*`, `http://localhost/*` | Connect to the user's local VANI API. Loopback ports are configurable. Requests use a scoped capture key.                                                                                                  |
| Optional `https://*/*`                     | Publisher PDF hosts are not known in advance. Request only the selected PDF host at runtime when the user chooses to include its PDF; the wildcard declaration is not an install-time grant to every site. |

**Remote code:** None. JavaScript, styles, validation, and metadata parsing are bundled in the ZIP. Retrieved article metadata and PDFs are treated as data.

**Data declarations:** Accurately disclose website content, selected source URLs/browsing-related information, and the stored capture authentication key as applicable to the current dashboard categories. Do not select “no user data” merely because VANI storage is local. Review the policy text against the exact dashboard questions and certify only statements the publisher can attest to.

## Reviewer instructions

1. Install/start VANI using the repository setup guide, including migration 004. VANI does not require a hosted account. A local Node/PostgreSQL or Docker environment is required for review.
2. Load the extension and generate a capture key in VANI Settings. Paste it into extension Settings and select **Connect and test**. Docker users should set the app URL to `http://127.0.0.1:3000`.
3. Visit a public arXiv abstract page, click the extension, create/select a collection, and save with its PDF. Grant arXiv access when requested.
4. Close/reopen the popup during a save, inspect completion, and open the saved work in VANI. Repeat capture to verify paper/PDF reuse.
5. Decline a PDF site's permission on a new site to verify that metadata still saves with a partial status; retry or attach the PDF in VANI.
6. Revoke the key in VANI Settings and verify that new captures require reconnection.

Native Chrome permission grant/deny prompts should receive a manual pass before submission. Automated browser testing pre-grants only its local HTTPS fixture host in a disposable extension copy; all other capture logic runs normally.

## Owner actions still needed

1. Sign in to the [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole). Complete any publisher registration, payment, verification, or account terms required by Google yourself.
2. Create a new item, upload the ZIP and listing assets, add the public privacy/support URLs, and complete the privacy/permission declarations.
3. Choose the distribution visibility. A private/tester or unlisted release can be useful for this first version because users need a local VANI installation.
4. Review the complete listing and submit it for Google's review. Publishing status and approval timing are controlled by Google; a valid ZIP is not store approval.
