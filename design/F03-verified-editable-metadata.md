# F03 — Verified, editable metadata

Status: implemented and validated. Version 1, September 8, 2026.

## Outcome

A researcher can correct a record, inspect where its values came from, retrieve authoritative metadata by identifier, and reconcile disagreements without losing their own decisions. Canonical values, source assertions, and user decisions remain separate. Verification describes bibliographic agreement, not scientific quality.

## Canonical fields

Editable title, abstract, ordered authors and editors, year, venue/container, DOI, publisher/place, publication date, online and print dates, volume, issue, pages, article number, edition, ISBN, ISSN, language, URL, publication type, and manifestation type. Personal names are structured; an organization can be retained as a single unsplit name. Publication type supports articles, books, chapters, proceedings papers, theses, reports, datasets, software, and other records. Required title; optional incomplete fields remain visibly incomplete. DOI/URL/date/year validation prevents malformed edits. ISBN/ISSN are preserved as supplied rather than automatically treated as verified identifiers.

Stable work ID and citation key are never regenerated by metadata edits. Other works sharing a venue or person are not mutated: an edit assigns/rebuilds the current work's author/venue references. Metadata edits preserve attachments, annotations, notes, collection memberships, and graph relationships. A changed title/abstract invalidates cached first-pass reports.

## Editor and review UX

Provide a **Review metadata** action in the reader, linking to a full-width `/works/:id/metadata` page. The page displays canonical values, verification state, saved revision, provenance/history, and a form for manual corrections. Library cards already link to the reader.

**Save corrections** submits only changed fields with the loaded revision. Changed fields receive a user lock; source refreshes cannot replace them. A stale revision returns a clear conflict and requires reload/review, not silent last-write-wins.

**Look up identifier** explicitly sends a DOI or arXiv ID to the supported public registry. Persist the returned source assertion and show a comparison table: current value, proposed value, source, retrieval timestamp, equivalence/difference/missing status, and user-lock status. Source lookup never edits canonical values. Import assertions and the original record snapshot are also reviewable sources.

Select fields individually and choose **Apply selected source values**. Locked fields require a separate explicit **Replace my corrections for these selected fields** choice. Choosing current values remains a recorded decision. A source conflict can be resolved with **Keep current values for unselected differences**. No blanket auto-accept is the default. Empty source values do not clear canonical fields unless selected explicitly.

## Provenance and verification

`metadata_assertion` stores work ID, source name, external identifier, source URL, raw payload, normalized asserted fields, retrieval time, and content hash. `metadata_decision` records each revision's field changes/confirmations, old/new values, origin, source assertion ID, timestamp, and user reason. `work.metadata_locks` identifies manual corrections. Existing `source_record` payloads remain intact; an initial snapshot provides an explicitly labeled baseline when older field-level provenance is unavailable.

Verification uses the existing public status vocabulary:

- `unverified`: manually entered/imported/snapshot data without supported authoritative corroboration.
- `partial`: an authoritative registry assertion has been retrieved/reviewed, but required identity fields are incomplete, deliberately overridden, or not all corroborated.
- `conflict`: the most recently considered authoritative assertion has unresolved material disagreements with nonempty canonical values.
- `verified`: title, ordered authors, year, publication type, and identifier agree with a supported authoritative source, with venue or publisher where applicable; the user has reviewed/applied that assertion. This release does not claim independent multi-source verification from two records from the same registry.
- Existing `verified_multi_source` records are not newly created by this workflow. A subsequent edit or review recomputes their state conservatively.

Normalize DOI prefixes/case, Unicode whitespace and punctuation for titles, dash variants for pages, and author order/names without throwing away originals. Initials versus complete given names may count as equivalent when family names/order agree; author additions/reordering and different title words are material differences. User-kept differences are recorded and result in `partial`, not a falsely verified record. A lookup failure leaves canonical data, locks, and prior verification unchanged. Generic uploads and browser extraction never constitute authoritative verification by themselves.

Changing a DOI to one already owned by a different work returns an identity conflict with a link to that work. It does not merge records or detach annotations (F04 handles merging). Source identity clashes are blocked at import commit as well.

## API and concurrency

- `GET /api/v1/works/:id/metadata` — canonical form, revision, locks, assertions, decisions, and completeness warnings.
- `PATCH /api/v1/works/:id/metadata` — revision-checked manual field patch plus optional reason.
- `POST /api/v1/works/:id/metadata/lookup` — retrieve/store one exact DOI/arXiv assertion; return updated review state.
- `POST /api/v1/works/:id/metadata/reconcile` — assertion ID, expected revision, selected fields, explicit lock override, and optional keep-current decision/reason.

Field decisions and canonical writes use one transaction and row lock. Lookups run outside transactions with bounded timeouts; saving the result uses the original revision so a slow lookup cannot supersede a concurrent edit. No LLM writes verified metadata. Raw source payloads remain local and available for inspection.

## Acceptance and validation

1. Correct title, ordered authors, book/chapter fields, and DOI; save/reload preserves values, work ID, key, and attached research objects.
2. A registry refresh presents differences without overwriting canonical fields or user locks.
3. Source-selected edits record provenance; locked fields reject implicit replacement and permit explicit replacement.
4. Equivalent punctuation, DOI prefixes/case, and initials do not become false material conflicts; missing authors, title changes, and year changes do.
5. Wrong-work DOI, stale revision, offline/not-found lookup, and malformed field patches return actionable errors without partial writes.
6. An incomplete or user-overridden record cannot become verified; generic imported assertions cannot produce authoritative verification.
7. Import/re-import and F01 capture preserve F03 corrections. A browser test covers manual editing, source comparison, deliberate reconciliation, and history.
